# Savour

[English](README.en.md)

**Save now. Savour later.**

> 收藏從未停止，行動從未開始。

內容常常存得亂七八糟，四散在書籤、按讚、截圖裡，結果真的有空想閱讀時，又陷入尋找循環。Savour 負責保存、整理：點一下，就把正在看的內容存進自己的 Notion 資料庫，作者、來源、發布時間、保存時間自動填好，全部放在同一個地方，可以搜尋、篩選，等有空再慢慢消化資訊。

可以保存網頁文章（新聞、部落格、維基百科……）、YouTube 影片，以及 Threads、噗浪、X、Instagram、Facebook、LinkedIn 的貼文，一篇一篇存進自己的 Notion 資料庫。只在你按下保存時運作，資料由你的 Chrome 直接送到你的 Notion，沒有中介伺服器。

## 會保存什麼

### YouTube 影片

- **保存什麼**：影片嵌入（在 Notion 裡直接播放）、頻道名稱與長度、資訊欄全文（網址會變成連結）、發布日期。資訊欄裡 `0:00 開場` 這樣的時間碼會整理成「章節」清單，點時間碼會跳到影片的那個時間點。「來源」欄位為 YouTube。
- **不保存**：影片檔本身、字幕／逐字稿、留言。
- 不同網址形式（`youtu.be`、帶時間或播放清單參數、Shorts）的同一支影片視為同一篇，不會重複保存。
- 直播只保存目前的影片資訊。

### Facebook 貼文

- **保存什麼**：個人、粉絲專頁與社團貼文的正文（emoji、連結保留）、貼文圖片、連結預覽、作者與發布時間。「來源」欄位為 Facebook。圖片由你的 Chrome 下載後上傳到你的 Notion，不會因為 Facebook 圖片網址過期而失效。
- 請先點開貼文的單頁（點貼文的發布時間），再按保存；動態牆上的貼文不支援直接保存。
- **限制**：圖片是畫面上顯示的尺寸，不是原圖；Facebook 不一定在頁面上提供發布時間，讀不到時「發布時間」欄位留空；留言、反應數與影片不保存；分享／轉貼別人的貼文只保存分享者自己的文字與畫面上的預覽圖，不處理被分享的原貼文。
- 同一則貼文用不同網址形式（`m.facebook.com`、帶追蹤參數）開啟視為同一篇。

### LinkedIn 貼文

- **保存什麼**：正文（連結、@提及保留）、圖片與 PDF 輪播的每一頁、貼文裡的連結卡片、作者與發布時間（由貼文編號推算，不受「2 週前」這種相對日期影響）。「來源」欄位為 LinkedIn。
- **轉貼**：保存轉貼者自己的評語，被轉貼的原貼文只放作者、一小段摘要和原貼文的連結書籤，點進去就能看完整內容；原貼文的圖片與全文不保存。
- 請先點開貼文的單頁（點貼文的發布時間），再按保存；動態牆上的貼文文字會被摺疊，不支援直接保存。
- **不保存**：留言、反應數，影片只保存文字與圖片。不同網址形式（`/posts/…`、`/feed/update/…`）的同一則貼文視為同一篇。

### 網頁文章

- **只保存正文**：用 Mozilla Readability（Firefox 閱讀模式使用的同一套方法）找出文章本體，導覽列、側欄的熱門新聞、廣告與頁尾不會存進來。
- **保留排版**：標題層級、段落、粗體／斜體、內文連結、項目清單、引言、表格、程式碼區塊都會轉成對應的 Notion 區塊。YouTube、Vimeo 影片會變成 Notion 可以直接播放的影片。
- **圖片**：保持在文章裡原本的位置，圖說一併保存。圖片由 Notion 從網站的公開網址匯入到你的工作區，原網站之後刪圖也看得到；Notion 抓不到的圖片（需要登入、擋外連的網站）會改成連結原圖。
- **標題、網站、作者、發布時間**：取自網頁本身提供的資訊。沒有寫作者時，「作者」欄位填網站名稱。
- 讀不到文章的頁面（例如網頁工具、影片頁）只保存標題、網頁簡介、代表圖與網頁書籤，並在擴充功能的「最近保存」提示「正文可能有遺漏」；這時可以改用反白文字保存需要的段落。
- 網址裡的追蹤參數（`utm_*`、`fbclid` 等）與 `#` 會去掉，同一篇文章不會因為從不同地方點進來而存成兩頁。
- 指向你電腦或區域網路（例如 `localhost`、`192.168.x.x`、路由器、NAS）的圖片不會下載，也不會在 Notion 裡連結；只有文章本身就在那個內網網站上時才會處理它的圖片。

### X（Twitter）

- **貼文正文**（含 emoji 與連結）、原尺寸圖片、連結預覽卡片（存成 Notion 書籤）。
- **作者自己的串文**：在貼文頁面上，緊接在這則貼文下面、同一位作者的貼文會接在同一個 Notion 頁面，遇到其他人的回覆就停止。作者回覆讀者、讀者的回覆都不會保存。
- **引用**：被引用的貼文只保留一行「引用：」加網址。
- 被 X 摺成「顯示更多」的貼文，擴充功能的「最近保存」會提示「正文可能有遺漏」；點開那則貼文後再保存就能讀到全文。影片不保存。

### Instagram

- **完整的說明文字**（頁面上被摺成「… 更多」的部分也會存）、作者、發布時間。
- **所有圖片**：輪播貼文的每一張照片依順序保存，使用最大尺寸。Reels 與影片保存封面圖片，影片本身不保存。
- 只保存貼文本身；留言、頁面下方「更多貼文」的內容都不會存。
- 在 Instagram 站內點進另一則貼文時，頁面資料還停留在前一則，保存前會**自動重新整理一次頁面**，跟 Threads 一樣。
- 需要在貼文頁（`instagram.com/p/…` 或 `/reel/…`）保存；動態牆上的貼文請先點開。

### Threads

- **主貼文正文**，包含被 Threads 摺起來的長文附件全文。
- **`1/N` 串文**：同一作者、明確標上 `1/N`、`2/N` 的續文會依編號排好，放在同一個 Notion 頁面。畫面順序被釘選打亂時，也會照編號排回來。
- **作者自己的補充**：作者直接回覆自己主文、但沒有編號的補充，排在串文後面。讀者留言、作者回覆讀者的內容都不會存。
- **圖片**：下載後上傳到 Notion，保持原本順序。頭像、表情貼圖、連結預覽卡片的縮圖不會被當成貼文圖片。
- **連結**：內文裡的網址在 Notion 可以直接點，即使 Threads 把它縮短成「…」也會指向完整網址。直接寫出的完整網址也會自動變成連結。只出現在預覽卡片的連結會存成 Notion 書籤。
- **引用**：被引用的貼文只保留一行「引用：」加網址，不會把別人的內容混進正文。
- **Threads 主題**、作者、發布時間與來源網址，存在資料庫欄位裡。

### 噗浪

- **噗文正文**、原尺寸圖片、連結（縮短的網址一樣可以點）與連結預覽卡片（存成 Notion 書籤）。
- **Plurk Paste 長文**：噗文附的 Paste 會讀出全文，直接放在噗文的 Paste 連結下面，Paste 連結之後原本還有的文字（例如標籤）則放在 Paste 全文的下方。工具會先以未登入的訪客身分讀取公開的 Paste；讀不到時，才在背景開一個分頁、用你自己的登入狀態讀完後關閉。都讀不到時，噗文照樣保存，並在擴充功能的「最近保存」提示「正文可能有遺漏」。
- **噗主自己的補充回應**：噗主在回應區延伸的內容會接在噗文後面；以「讀者名: 」開頭的回覆、以及其他人的回應都不會保存。只會保存畫面上已載入的回應。
- 好友限定的噗：你看得到的內容才能保存，存進 Notion 後就是你的私人副本，請勿外流。

## 不會做的事

- 不會在你沒有按保存時讀取任何網頁。
- 已經存在的 Notion 頁面不會被改動，除非你按「更新 Notion 頁面」、補上缺少的串文，或把選取文字加到那一頁。
- 不會在背景重新下載網頁（唯一的例外是 YouTube：站內換到另一支影片後，會重新讀取那支影片的頁面），不會登入，也不會繞過付費牆或私人帳號的限制。
- 沒有分析追蹤，也不會把資料送到你保存的網站與 Notion 以外的地方。

## 安裝

1. 從 Chrome 線上應用程式商店安裝；或下載 ZIP 後解壓縮，在 `chrome://extensions` 開啟「開發人員模式」，按「載入未封裝項目」並選擇含有 `manifest.json` 的資料夾。
2. 建議把擴充功能釘選在工具列。

## 第一次設定

### 1. 建立 Notion 連線

1. 到 [Notion Integrations](https://www.notion.so/profile/integrations) 建立 Internal Integration，開啟「讀取內容、插入內容、更新內容」權限。
2. 複製 Integration Token（請勿貼到聊天或公開場合）。
3. 打開擴充功能的設定頁，在「Notion 連線」貼上 Token，按「儲存設定」或「測試 Notion 授權」。

Token 預設只保留到 Chrome 完全關閉；勾選「在這台電腦記住 Token」就不用每次重貼，但請只在自己的電腦上勾選。

### 2. 選擇整理庫

**使用既有的資料庫**

1. 在 Notion 打開要用的資料庫，右上角「⋯」→「Connections」，加入剛才的 Integration。
2. 回到設定頁按「載入可用資料庫」（已有 Token 時會自動載入），從清單選擇，再按「使用這個整理庫」。
3. 空白資料庫也可以，缺少的欄位會自動補上。

清單裡找不到時，可以展開「進階：手動貼上資料庫網址」。

**讓工具建立新的整理庫**

在 Notion 建立一個空白頁面並加入 Integration，把網址貼到「建立新的整理庫」，按「建立 Notion 整理庫」。

**更換整理庫**

隨時可以回設定頁選另一個資料庫。換之前會先確認；換了之後，工具會清掉本機的「已保存」紀錄，改讀新資料庫的內容。兩個資料庫裡的文章都不會被刪除或修改。還有文章在「等待中」時不能更換。

### 3. 介面語言

Savour 的畫面、提示訊息與右鍵選單有正體中文與英文兩種語言。預設跟隨瀏覽器的語言，也可以按設定頁右上角的「中／EN」切換成固定的中文或 English，切換後設定頁會重新載入。

新建整理庫的欄位名稱與「來源」選項跟著當時的介面語言：英文介面建立的是 Name、Source URL、Source（選項 Plurk、Web…）等英文欄位。整理庫建立後語言就固定，之後切換介面語言不會改動它；工具是靠欄位的 ID 認欄位，所以你也可以自己把欄位改成喜歡的名字。頁面裡工具自己寫的文字（「引用：」「擷取提醒」等）則跟著保存當下的介面語言。

## 使用方式

| 想做的事 | 怎麼做 |
|---|---|
| 保存目前這篇文章或貼文 | 打開網頁文章、YouTube 影片（`youtube.com/watch?v=…`）、Threads 單篇貼文、噗浪單篇噗文（`plurk.com/p/…`）、X 貼文（`x.com/帳號/status/…`）、Instagram 貼文（`instagram.com/p/…`），或 Facebook、LinkedIn 的貼文單頁，按擴充功能的「保存目前頁面」、按 `Alt+S`，或在頁面上按右鍵選「保存目前頁面到 Notion」 |
| 用最新內容更新已保存的頁面 | 打開已經保存過的文章或貼文，按擴充功能的「更新 Notion 頁面」，再按一次確認 |
| 只保存一段文字 | 反白文字後按右鍵選「將選取文字保存到 Notion」→「存成新頁面」；或打開擴充功能，按「保存目前選取文字」旁的「存成新頁面」 |
| 把一段文字加到已保存的頁面 | 反白後按右鍵選「將選取文字保存到 Notion」→「加到這篇的 Notion 頁面」，或「加到其他頁面…」在擴充功能圖示下方跳出的選單從整理庫挑一頁；擴充功能裡的「加入現有頁面」按鈕開啟的是同一個選單；也可以替它指派快捷鍵（見下方） |
| 保存動態牆上的某一篇 | 先點開那一篇（點發文時間），再按「保存目前頁面」或快捷鍵 |

**快捷鍵**：「保存目前頁面」預設是 `Alt+S`；「保存選取的文字」（開啟選擇頁面的選單）預設不指派，避免和其他程式衝突。兩者都可以在 `chrome://extensions/shortcuts` 改成你習慣的按鍵。

**從動態牆點進貼文時**：Threads 這時還沒把這篇的完整串文資料放進頁面，所以按保存時，工具會**自動重新整理一次頁面**、等貼文載入後再保存。效果跟你自己按 F5 一樣。

**把選取文字加到既有頁面**：適合補上前後文，例如在噗浪把讀者的留言和噗主的回應一起反白，加到那篇噗的 Notion 頁面。文字會用分隔線隔開、接在頁面最後面，只放你選的文字，原本的內容和筆記都不會被動到。選擇頁面的選單（從擴充功能圖示下方跳出）會列出這篇的頁面和最近用過的頁面，也可以輸入標題搜尋，但只限目前的整理庫。這個選單是擴充功能自己的畫面，不是網頁的一部分，所以你正在看的網站讀不到你 Notion 頁面的標題，也無法替你按下選項；網頁上的提示也只會說「加到這篇的 Notion 頁面」，不會顯示頁面標題。同一段文字已經在那頁上時不會再加一次；如果你在 Notion 刪掉了加入的文字，想重新加入，請先按一次「同步 Notion」。

**重複保存**：已經存過的文章會顯示「已經保存過了」，不會再建第二頁，也不會改動原頁面。

**更新已保存的頁面**：文章內容改了（新聞更新、部落格修訂、串文又多了幾則），打開那篇按「更新 Notion 頁面」，工具會重新讀取頁面，把 Notion 頁面裡的**原文**換成最新內容，標題、作者等欄位一起更新。

- 你寫在原文**上面或下面**的筆記、用「加到這篇的 Notion 頁面」加進來的文字都會留在原位。
- 直接改在原文段落裡的字、或插在原文段落之間的內容會跟著原文一起被換掉，請把筆記寫在原文上下方。
- 「保存時間」不會改變。

**串文缺段**：如果保存時 `1/N` 串文沒有全部載入，擴充功能的「最近保存」會提示「串文可能不完整」，「待補完串文」也會列出來。之後再打開那篇按一次「保存目前頁面」，工具只會把**缺少的段落接在原頁面最後面**，原本的內容和你的筆記都不會被動到。補齊後，提示會自動消失。

## Notion 頁面與欄位

頁面內容從原文開始：網頁文章保留原本的段落、標題與圖片位置；貼文的主貼文、各段串文、作者補充之間用分隔線隔開，`1/N` 序號放在每段最後一行，圖片接在所屬文字後面。

新保存的頁面會用來源網站的圖示當 Notion 頁面 Icon，一眼就看得出是從哪裡存的。更新既有頁面不會改動它的 Icon。

資料庫共有 10 個欄位，網頁、Threads、噗浪、X、Instagram、YouTube、LinkedIn 與 Facebook 存在同一個資料庫，用「來源」欄位區分。欄位可以自己改名，但請不要刪除或改變欄位類型；被刪掉的欄位，工具下次連線時會補回來。其中「擷取鍵」「貼文編號」「原文範圍」是工具內部使用的欄位，第一次建立或連接整理庫時會自動在表格檢視中隱藏；想看的話可以在 Notion 檢視的「屬性」選單打開，之後工具不會再把它們藏起來。

| 欄位（英文整理庫） | 說明 |
|---|---|
| 名稱（Name） | 網頁文章用文章標題；貼文取原文開頭，最多 30 字 |
| 來源（Source） | 網頁（Web）、Threads、噗浪（Plurk）、X、Instagram、YouTube、LinkedIn 或 Facebook |
| 來源網址（Source URL）、作者（Author）、發布時間（Published） | 原文資訊（網頁沒有寫作者時填網站名稱） |
| 保存時間（Saved） | 你保存的時間 |
| Threads 主題（Threads topic） | 作者選的主題標籤 |
| 擷取鍵（Capture key）、貼文編號（Post ID） | 判斷「是否已保存」用（噗浪的貼文編號是網址最後那段，X 是 status 後面的數字，Instagram 是 /p/ 後面的代碼，網頁沒有貼文編號）。預設隱藏，請不要刪除 |
| 原文範圍（Original range） | 記錄頁面裡哪一段是保存的原文，「更新 Notion 頁面」只會換掉這一段。預設隱藏，請不要刪除或修改 |

**打開頁面時也不想看到內部欄位**：Notion 沒有開放工具設定頁面裡的屬性顯示，需要你自己設定一次，之後整個資料庫的每一頁都會套用：

1. 打開任一篇已保存的頁面，在頁面上方的屬性區，點「擷取鍵」左邊的欄位名稱。
2. 選「屬性可見性」（Property visibility）→「始終隱藏」（Always hide）。
3. 「貼文編號」「原文範圍」也做一次。

隱藏後屬性區下方會出現「N 個隱藏屬性」，需要時點開仍看得到。

## 最近紀錄與同步

- **同步 Notion**：重新讀取整個整理庫，讓本機紀錄和 Notion 一致。在 Notion 直接刪掉文章後，按一次同步就能重新保存那篇。
- **清除紀錄**：只清空擴充功能畫面上的最近紀錄，不影響 Notion，也不會讓文章變成「沒存過」。
- **重試失敗項目**：網路或 Notion 暫時出錯時，失敗的文章會留著，可以手動重試。
- **匯出清單**：匯出 JSON，核對已保存、等待中與失敗的項目。

## 已知限制

- 只能保存頁面當下已載入、你有權查看的內容。需要登入或付費才看得到的文章，要在登入狀態下、文章已顯示時保存。
- Chrome 內建頁面、Chrome 線上應用程式商店與 PDF 檔案無法保存。
- 網頁的版面千變萬化，少數網站可能抓到多餘的段落（例如文末的 App 下載說明）或漏掉部分內容；遇到時可以改用反白文字保存。
- X 有新舊兩種頁面版面，工具都能辨識；X 改版可能影響辨識，抓不到時會取消保存，不會亂存。
- Instagram 改版導致讀不到頁面資料時，會改存頁面摘要裡的說明文字與第一張圖，並在擴充功能的「最近保存」提示「正文可能有遺漏」。
- 不下載影片，只保存圖片。圖片會占用 Notion 工作區空間；單張超過 20 MB 或 30 秒內下載不完的圖片會放棄，文字照樣保存，擴充功能的「最近保存」會提示「圖片未完整」。
- 長文附件視窗裡被縮短的網址目前無法還原成完整連結；長文裡直接寫出的完整網址則可以。
- 發布時間只讀取頁面上的精確時間，不會用「3 天前」這類文字推算；讀不到時留空。
- Threads 改版可能影響文字、圖片、串文序號或引用範圍的辨識。工具抓不到時會留空、在「最近保存」提示，或取消保存，不會自行猜測。遇到這種情況可以先改用「反白文字保存」。

## 開發

需要 Node.js 18 以上版本。

```bash
npm install
npm test
npm run check
```
`npm run lint` 會用 ESLint 檢查全部程式碼；`npm run typecheck` 用 TypeScript 檢查 JSDoc 型別（設定在 `jsconfig.json`，只檢查不輸出）。

### 專案結構

```
manifest.json        擴充功能設定
background.js        背景服務：建立共用服務、處理事件與訊息
background/          背景服務的各個部分（分頁、整理庫、從目前分頁保存、選頁視窗、狀態與同步、Plurk Paste）
content/             各網站的內容程式：Threads、X、Instagram、Plurk、YouTube、LinkedIn、Facebook、一般網頁（含 content.css 與提示訊息）
pages/               擴充功能自己的頁面：popup/、options/、picker/，以及共用色票 tokens.css
model/               把頁面傳來的資料整理並驗證成可信的擷取資料
notion/              Notion 欄位定義、頁面內容建構、API 請求與讀寫流程
queue/               保存佇列與重試
storage/             設定、本機狀態與保存前的圖片暫存
lib/                 各處共用的純函式（文字清理、網址解析、去重鍵）
i18n/                介面語言：index.js 負責翻譯，en.js 是英文字典
_locales/            商店顯示用的名稱與說明（英文、正體中文）
vendor/              第三方程式（Mozilla Readability）
icons/               圖示：16、32px 由 scripts/build-icons.js 產生（npm run icons），48、128px 是手繪插圖
scripts/             產生工具列圖示的腳本
store/               Chrome 線上應用程式商店文案
tests/               測試與測試用網頁範本
types.d.ts           資料形狀的型別宣告（只供編輯器與檢查使用）
```
